- **ci:** the Release-Green sweep no longer runs as one job, because one job cannot finish it. A runner on this repository stops at ~60 minutes ("The runner has received a shutdown signal") and the slow suites' own ceilings are 80 + 15 + 40 + 20 = 155 minutes serial, so four consecutive full sweeps were killed at exit 143 — run 35496465106 at 60m11s, with every static and drift gate already green and the suites 54 minutes into silence — and no full-CI verdict existed for the release branch. The sweep is now `resolve` (branch → one exact SHA) → seven `slow-suite` jobs (unit ×4, integration ×2, vitest, each under the ceiling) → `release-green`, which runs the static, drift, full-ci, package-artifact and boot gates and merges the shards' reports into the verdict. Every job checks out the SHA `resolve` produced, so the merged report belongs to one commit. The shards measure and never judge: a red suite still exits 0 so its report arrives, and the aggregator runs on `!cancelled()` rather than `success()` so a shard that died still gets a verdict. The new risk — a job reporting green while measuring nothing — is what the guards are for: `--expect-slow` names every shard id the matrix produces and records a missing one as a HARD failure ("it did not run, so it is NOT green"), an unknown `--slow-gates` id throws instead of selecting nothing, a run that records zero gates fails for that reason alone, and a test derives the expected ids from the matrix so a stale list fails closed.
