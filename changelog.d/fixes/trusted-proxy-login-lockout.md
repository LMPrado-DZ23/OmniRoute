- **fix(security):** behind a reverse proxy **on another machine**, anyone on the internet could lock the owner out of their own panel — five wrong passwords, fifteen minutes, repeatable. Forwarding headers (`X-Forwarded-For`, `X-Real-IP`, `CF-Connecting-IP`) are trusted from a loopback peer only, which is correct for a proxy on the same host; from another machine the peer is a LAN address, the headers are ignored, and every visitor collapses onto the proxy's single IP, so the login lockout counted the whole internet as one client. `X-Forwarded-For` could not fix it, because trusting it from an arbitrary peer is exactly the spoofing hole the loopback rule exists to prevent. `OMNIROUTE_TRUSTED_PROXY_IPS` lets the operator name their proxy by exact IP: the peer must **match**, so a forged header from any other address is still ignored, and unset — the default — behaviour is byte-identical. Exact addresses only, no CIDR: a subnet parser here is a place for an off-by-one to silently widen who gets believed about their own identity. 16/16 tests, including one that asserts a declared proxy does not make every peer trusted.
