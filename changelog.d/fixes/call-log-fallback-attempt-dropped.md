- **fix(logs):** the request that answered the client after a combo fallback was missing from the request log. `trackPendingRequest` deliberately gives every target attempt of one client request the same pending id (so a dashboard tab's live poll survives a fallback), and the attempt logger used that id as the `call_logs` primary key, so the second attempt — the one that succeeded — hit `UNIQUE constraint failed: call_logs.id`, was dropped with a console error, and left only the failed attempt in the log. `saveCallLog` now picks a free id (`<id>`, `<id>~2`, `<id>~3`, …) before inserting, so every attempt is kept and the first row keeps the plain id. Found by `combo-routing-e2e` ("priority combo can repeat the same provider/model with different fixed accounts"), red in every full sweep on the release line; pinned by `tests/unit/call-log-duplicate-id.test.ts`, which fails without the change.
