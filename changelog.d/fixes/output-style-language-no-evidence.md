- **fix(sse):** output-style language auto-detection overrode a pinned language with English whenever the message had no recognised keyword. `detectCompressionLanguage` returns `"en"` for zero hits (right for the input engines, which have nothing else to fall back to), and `resolveOutputStyleLanguage` used it as if it were evidence: a combo pinned to `pt-BR` answered a Portuguese message like "Resuma esta implementacao." with the English instruction, because none of the pt-BR hint words happened to be in it. Detection now has a null-returning variant, `detectCompressionLanguageOrNull`, and a message with no evidence keeps the configured default; positive evidence (German, Russian, …) still wins over the default. This was two of the failing tests in the sweep's integration shard 1 (`chatcore-compression-integration`), red since `#12289` added `autoDetect` to output styles on 2026-09-01.
