- **fix(ci):** a changelog reconciliation written on Windows was verifiable only on Windows. `changelogSha256` hashed raw bytes, and the two sides of the comparison arrive differently: the base comes from `git show <ref>:CHANGELOG.md`, which is always the stored LF content, while the result is read from the working tree — CRLF on a checkout with `core.autocrlf=true`. The same file therefore hashed `774e2524…` locally and `66e20f2a…` in CI, so the record passed on the machine that wrote it and failed the merge-integrity gate with no indication why. The digest now normalises CRLF to LF before hashing, which leaves every existing record valid (they were all LF-derived) and makes a reconciliation bind content rather than a checkout. Two tests: one asserts the digest is line-ending independent while still being a real digest, the other asserts the newest ledger record still matches `CHANGELOG.md`, so a record that stops guarding fails loudly instead of quietly.
