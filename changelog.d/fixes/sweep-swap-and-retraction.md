- **fix(ci):** retraction and a testable fix for the Release-Green sweep's artifact gate. Both sweeps on 2026-09-20 died at `exit 143` about six minutes into `check:pack-artifact`, and I explained it — in the v3.8.55 tag message, the workflow, the validator's own doc comment, the audit record and my notes — as "a hosted runner cannot fit a full `next build`". **That was wrong and I had not measured it.** `electron-release.yml`'s Next build completes on plain `ubuntu-latest` in about 11.5 minutes, and `build.yml` dispatched by hand on the v3.8.55 tag completed `build:release` (Next + CLI bundle + SHA) in 7m17s once it had 10 GB of swap (run 36199521486). The real difference from the sweep is that the sweep's aggregator job provisioned no swap, and swap is what absorbs Turbopack's native allocation peak, which `--max-old-space-size` does not bound (#6409) — a hypothesis, which the next sweep now tests. The workflow provisions that swap on hosted runners and runs the artifact gate only if `swapon` actually succeeded (`provisioned` is emitted after it, never before, pinned by a test); otherwise the gate is still recorded as unmeasured, now with the true reason. The false sentence is removed from the workflow, from the validator's JSDoc and from the unmeasured reason string, retracted in a dated correction in `audit/FINAL_THREE_AGENT_REVIEW.md`, and a test keeps it from returning as a fact. What was true and stays true: no self-hosted runner is registered (`total_count: 0`), so `USE_VPS_RUNNER` is a dead flag and the remedy I suggested did not exist. Half of the gate needs no build at all — `check:pack-artifact --policy-only` runs on every PR via `pack-policy` and passes.
