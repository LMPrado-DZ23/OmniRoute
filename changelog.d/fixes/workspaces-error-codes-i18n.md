- **fix(workspaces):** every refusal on the Workspaces page was shown in English, in every language — including for the locales that have a real translation. The page rendered the server's English `message` verbatim, even though `/api/workspaces/**` already answered with a machine-readable `code` on some refusals. Codes are now on all of them (`authentication_required`, `viewer_readonly`, `workspace_not_found`, `project_not_found`, `member_not_found`, `name_taken`, `budget_exceeds_parent`, `workspace_not_empty`, `project_not_empty`, `key_in_other_workspace`, `invalid_json`, `internal_error`), the client throws a `WorkspaceApiError` carrying the code, and the page translates it through `workspaces.errors.<code>` in all 42 locales — written out properly in Portuguese (pt, pt-BR), Spanish, French, German, Italian and Vietnamese, English elsewhere until the translation pass runs. A code the dashboard does not recognise falls back to the server's message, so a refusal added later is untranslated rather than blank. "Workspace not found" still answers identically whether the workspace does not exist or the caller is not a member — the code is part of that shared body, so a foreign id still cannot be probed. Guarded by 6 tests, one of which reads the codes back out of the handlers so the two cannot drift apart.
