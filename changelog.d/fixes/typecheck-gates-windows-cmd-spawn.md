- **fix(tooling):** three of the four typecheck gates could not run on Windows. `check:dashboard-typecheck`, `check:open-sse-typecheck` and `check-api-typecheck.mjs` spawned `npx.cmd`, and since CVE-2024-27980 Node ≥ 20 refuses to spawn a `.cmd` without a shell (`spawnSync npx.cmd EINVAL`) — so they crashed with a stack dump and exit 1 in about five seconds instead of running or skipping. Nothing reported it because CI is Linux. They now go through the repo's own shim-free runner (`scripts/build/buildToolRunner.mjs`), which executes `typescript`'s JS entry with the current Node binary. That runner used to discard the tool's stdout (`@returns {void}`); it now returns it, because these gates parse the `tsc` report — a non-zero exit still carries `stdout` on the thrown error, which the gates rely on. Existing callers ignore the return value and are unaffected. Run for real on Windows afterwards: `dashboard` and `open-sse` exit 0 with 0 errors within baseline, `api` exits 0, and `typecheck:core` / `typecheck:noimplicit:core` were already clean. Guarded by 6 tests, including one that reads each gate's **code** (comments stripped, because the comments explaining the fix mention `npx.cmd`) and one that pins the Windows spawn plan from a Linux runner.
